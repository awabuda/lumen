# P22.7 design lock — native binding ABI drift auto-repair

> **Design-only pass.** P22.7 closes the footgun that P15
> (`pnpm rebuild:native`) shipped the **manual** fix for but
> didn't ship the **automatic** detection of. The choice,
> the framework comparison, and the design constraints are
> all locked here. The first P22.7.x implementation commit
> is the next step.

## 0. Why P22.7

### 0.1 4-framework fetch verification (2026-07-15)

The P22.7 surface — automatic detection + repair of a
native binding ABI drift between a package's prebuilt
`.node` and the current Node runtime — is **not** a
documented feature in any of the four reference frameworks.
That gap is the rationale for shipping it.

| Framework | URL fetched on 2026-07-15 | Key takeaway for P22.7 |
| --- | --- | --- |
| **Claude Code** | `https://docs.claude.com/en/docs/claude-code/troubleshooting` (re-fetched 2026-07-15) | The troubleshooting page covers performance / stability / search problems (high CPU, large tables, auto-compaction, hangs, search). The "Troubleshoot installation and login" sibling covers PATH / EACCES / TLS / update-download errors. **No documented "native module ABI mismatch" repair flow**. Claude Code itself has very few native deps (Node + npm), so the footgun doesn't surface for them. |
| **LangGraph 1.0** | `https://docs.langchain.com/oss/python/langgraph/installation` (404 — page no longer at that URL) and `https://blog.langchain.com/langgraph-v1-0/` (re-fetched 2026-07-15) | LangGraph 1.0 ships as a Python package; the equivalent footgun (Python C-extension rebuilt for one interpreter version, then run under another) is mitigated by `pip install --force-reinstall` and `pyenv` conventions, but is **not** an automated, in-repo hook. **No precedent.** |
| **OpenClaw** | `https://openclaw.ai/blog` (re-fetched 2026-07-15) | The blog has 11 posts (Foundation, Skill Workshop, NVIDIA security, "Safer Than YOLO" auto-mode, lighter-core-sharper-claws, security roadmap, OpenAI models, "rough week" stability report, security-in-public, VirusTotal). The lighter-core-sharper-claws post (May 28) covers faster turns / fewer deps / cleaner shape but **does not ship an automated native-binding drift hook**. **No precedent.** |
| **Hermes Agent** | `https://hermes-agent.nousresearch.com/docs/` (re-fetched 2026-07-15) | The docs index lists Installation / Quickstart / Configuration / Tools / Memory / Skills / MCP / Voice / SOUL.md / Context Files / Security / Architecture. **No documented "native binding ABI drift" check** — Hermes is a CLI that wraps Python-side tools and an LLM API; the surface is different. **No precedent.** |

**Synthesis**: none of the four reference frameworks
documents an automatic "detect a stale native binding +
rebuild it before you hit it" hook. P22.7 is a lumen-side
scaffold hardening. The closest patterns:

- **LangGraph Python**: relies on the user to `pip
  install --force-reinstall`. There is no in-repo guard.
- **OpenClaw**: relies on supply-chain whitelisting
  (`pnpm.onlyBuiltDependencies`-style) at install time.
  Once installed, drift is the user's problem.
- **Claude Code**: pure-JS package, drift is structurally
  impossible. They don't have the footgun.
- **Hermes**: same as Claude Code — pure-JS CLI surface,
  no native deps in the user's hot path.

P22.7 closes the gap for lumen (which has `better-sqlite3`
in `@lumen/memory`). It does **not** try to be a general
"detect all native deps" tool — that would be P23+
territory and out of scope for a 1-P design pass.

### 0.3 Why P22.7 is the right slot (not P23+)

- **It is the natural follow-up to P15.** P15 commit
  `0a75e2b` explicitly framed itself as "P9-P14 session log
  bit us 3+ times". The P22.6 + P22.5 sessions (2026-07-13
  → 2026-07-15) hit it again. The gap is now mature enough
  to ship a fix, not a workaround.
- **The user-facing surface is small.** One new script,
  one new doctor line, one new postinstall hook. ~150
  lines of code + ~120 lines of tests.
- **The change is backward-compatible.** No schema change,
  no API change, no public type change. A `minor` bump
  on `@lumen/cli` and `@lumen/memory` is the right
  changesets classification (P22.5 + P22.6 used minor
  too).
- **P22.7 does not need a new framework precedent.** The
  4-framework fetch above is honest about that. The
  rationale is "lumen has this dep, no other framework
  has the dep in their hot path". A narrow, focused,
  one-dep scope is the right shape for a single P-ticket.

## 1. P22.7 core definition

P22.7 makes the **detection** of a `better-sqlite3` ABI
drift automatic at `pnpm install` time, and keeps the
**repair** opt-in via the existing `pnpm rebuild:native`
command. The four-shape design:

1. **`scripts/abi-drift-check.mjs`** — a new top-level
   script (Node ESM, zero deps beyond Node stdlib) that
   reads the on-disk `.node` binary's recorded
   `NODE_MODULE_VERSION` (macOS: parse the Mach-O
   `LC_BUILD_VERSION` `minos` field equivalent via the
   segment; Linux: parse the ELF `EI_ABIVERSION` and
   adjacent `nodearch` string; Windows: parse the PE
   optional-header major/minor OS-version and the linked
   Node arch), compares it against the runtime
   `process.versions.modules`, and prints either
   `[OK] native ABI matches (compiled N, runtime N)` or
   `[WARN] native ABI drift detected: compiled N, runtime M`.
   On drift, exits 1 unless `LUMEN_ABI_SKIP_CHECK=1` is
   set, **and** if `process.stdout.isTTY` is true (so CI
   does not get an interactive rebuild), it runs
   `pnpm rebuild:native` itself and prints
   `[WARN] auto-rebuild succeeded` on success or
   `[FAIL] auto-rebuild failed: <stderr>` on failure.
2. **The script is wired as the root `postinstall` hook**
   in `package.json`. pnpm runs it after every `pnpm i`.
   This is the P15 `onlyBuiltDependencies` white-list's
   companion: P15 lets the install-time rebuild run, P22.7
   detects when the *cached* binding has drifted since the
   last `pnpm i`. Both pieces need to be in place.
3. **`lumen doctor` gains a `[OK/FAIL] Native ABI` line**
   that runs the same detection against the running
   `node`. If the line is FAIL, doctor exits non-zero,
   matching the existing "1 check(s) failed" pattern.
4. **An escape hatch**: `LUMEN_ABI_SKIP_CHECK=1` opts the
   postinstall hook out (no check, no rebuild, exit 0).
   Documented in the changeset and the operator guide.

### 1.1 Why ELF/Mach-O/PE header parsing and not a probe

The probe path — `try { require('better-sqlite3'); new
Db(':memory:') }` — has two problems:

1. **You can't probe what you've just broken.** If the
   binding has drifted, the probe itself crashes, and
   then you can't tell whether it crashed *because* of
   drift or because the probe script has a typo. The
   script is fragile in the exact state it needs to
   diagnose.
2. **It couples the check to the binding being loadable**
   in the same Node version the check is running under.
   That defeats the purpose: the check's job is to spot
   the mismatch, but the check itself is running in the
   mismatched runtime.

ELF/Mach-O/PE header parsing is a pure stdlib +
`fs.readFileSync` operation. No native binding involved.
No probe needed. The 3 platform parsers are ~80 lines
total and have no transitive dependencies.

The trade-off: header parsing is **read-only** — it
cannot fix anything. Repair is delegated to `pnpm
rebuild:native`, which already exists.

### 1.2 Why detect-then-rebuild, not detect-then-warn-only

P15 commit `0a75e2b` shipped the rebuild path as a
manual command. P22.7 makes the **detection** automatic.
The user's choice "auto rebuild + WARN" was made on
2026-07-15 (P22.7 session): drift → run the existing
rebuild command → red-text WARN with the before/after
NODE_MODULE_VERSION. This is the right call because:

- The user has already opted in to the rebuild path by
  declaring `pnpm.onlyBuiltDependencies: ["better-sqlite3"]`
  (P15). The postinstall hook reuses that whitelist; it
  does not introduce a new side effect.
- The cost of a rebuild is bounded: better-sqlite3's
  prebuild-install is the fast path (~5s on M-series
  Macs), and the node-gyp fallback is the slow path
  (~30s). pnpm install + the hook's rebuild adds <10s in
  the happy case.
- A WARN-only flow would force every operator to learn
  the `pnpm rebuild:native` command. The whole point of
  P22.7 is to remove that learning cost.

### 1.3 The four sub-tickets

P22.7 ships in four small commits, following the P22.6
shape (4 sub-tickets → 4 feature commits + design lock +
TASKS row):

- **P22.7.1 — `scripts/abi-drift-check.mjs`** + its
  unit tests + `.changeset/p22-7-abi-drift.md`. The
  script does platform detection, header parsing, drift
  reporting, and the optional rebuild invocation.
- **P22.7.2 — `lumen doctor` native ABI line** +
  one new test in `apps/cli/test/doctor-native-abi.test.ts`.
  The doctor command gains one `[OK|WARN|FAIL]` line;
  FAIL makes the doctor exit non-zero.
- **P22.7.3 — `postinstall` hook** in root
  `package.json`. The hook runs the script; the
  `LUMEN_ABI_SKIP_CHECK` env var is documented in the
  changeset and the operator guide.
- **P22.7.4 — operator guide**. A new
  `docs/ABI-DRIFT.md` covering: when drift happens,
  how to read the doctor output, the env escape hatch,
  CI behaviour, and the relationship to P15.

TASKS.md gets one row per sub-ticket and one P22.7
design-lock row, matching P22.5 / P22.6.

### 1.4 What P22.7 does NOT do

P22.7 is **narrow** by design. It does not:

- Detect drift in any native binding **other** than
  `better-sqlite3`. Adding a new dep would require a new
  config block (which path to probe, which header to
  parse) and is a P23+ candidate.
- Touch the `pnpm.onlyBuiltDependencies` whitelist. P15's
  whitelist is still the install-time gate. P22.7 is the
  post-install drift gate. Two separate surfaces, one
  decision (the whitelist) + one check (P22.7).
- Auto-rebuild on every doctor run. Doctor is
  **read-only**. It reports; it does not mutate.
  Rebuilding on every doctor would surprise users (a
  `lumen doctor` should never change the working tree).
- Ship a generic "node version manager" tool. The script
  reads the binding's recorded ABI, period. It does not
  try to be smart about which Node version to switch to.
- Replace `pnpm rebuild:native`. That command stays. The
  postinstall hook calls it; doctor tells you when to
  call it; CI can call it directly. The path is the
  same; P22.7 just adds a trigger.

## 2. P22.7 task breakdown

### 2.1 P22.7.0 — `scripts/abi-drift-check.mjs`

- **`scripts/abi-drift-check.mjs`**: a Node ESM script
  (~150 lines). Entry point exports
  `checkAbiDrift({ cwd, runtimeModules, onWarn, onRepair })`
  for testability, plus a `main()` that:
  1. finds `node_modules/.pnpm/better-sqlite3@*/node_modules/better-sqlite3/build/Release/better_sqlite3.node`
     via a `glob`-style scan (manual — no `glob` dep).
  2. parses the file's recorded NODE_MODULE_VERSION
     using a per-platform parser.
  3. compares against `process.versions.modules`.
  4. prints one of the three lines (OK / WARN drift /
     FAIL parse error).
  5. if drift + TTY + !LUMEN_ABI_SKIP_CHECK → spawn
     `pnpm rebuild:native` and report.
- **Platform parsers** (each ~20 lines):
  - **macOS** (Mach-O): read magic + `LC_BUILD_VERSION`
    load command; the `minos` field is the min-OS, not
    the ABI. The actual ABI is in a separate string
    table — the `prebuild-install` script writes a
    comment-like string into the binary via `clang`'s
    `-Wl,-sectcreate` trick. P22.7's mac parser scans
    for that string; if absent, it falls back to "ABI
    unknown" + WARN.
  - **Linux** (ELF): parse the `PT_INTERP` /
    `.note.GNU-stack` segments, scan for the
    `NODE_MODULE_VERSION=X` string the `prebuild-install`
    script embeds. Same fallback.
  - **Windows** (PE): parse the export table and the
    optional-header; the `prebuild-install` script
    writes the ABI into the file's `TimeDateStamp`
    field via a small post-link step. P22.7's PE parser
    reads `TimeDateStamp` and looks up a known
    ABI-by-year table.
- **Tests** (`scripts/test/abi-drift-check.test.mjs`):
  - happy path: drift-free .node file → exit 0
  - macOS Mach-O header parse: synthetic file → ABI 127
  - Linux ELF header parse: synthetic file → ABI 115
  - Windows PE header parse: synthetic file → ABI 115
  - drift detection: real `better_sqlite3.node` from
    lumen → assert the parser returns its actual ABI
  - rebuild spawn: with a stub `pnpm` → verify the
    rebuild command is invoked
  - LUMEN_ABI_SKIP_CHECK=1 → no rebuild, exit 0
- **Changeset** (`.changeset/p22-7-abi-drift.md`): minor
  bump on `@lumen/cli` (doctor surface) + `@lumen/scripts`
  (the new package, see below).

The script does not live in `apps/cli/` because it is
not a CLI surface — it is a build-time tool, run via
`pnpm install`. It also does **not** introduce a new
`packages/scripts/` workspace, because CLAUDE.md rule
#9 forbids new top-level packages without maintainer
sign-off, and the tier diagram's lowest tier is already
populated (`llm`, `config`). Instead:

- The script lives in the existing top-level
  `scripts/` directory, next to `lumen.rb` and
  `smoke-test.sh`. That directory is the in-tree home
  for "build-time, not-CLI, not-tier-X" utilities.
- The script is a Node ESM `.mjs` file with **no
  transitive dependencies beyond Node stdlib**. pnpm
  install does not need to add anything to the lockfile.
- The doctor CLI does **not** import the script via a
  package import. Instead, it `spawn`s `node
  scripts/abi-drift-check.mjs --json` and reads the
  JSON response. This keeps the tier diagram honest
  (no cross-tier import) and avoids the `apps/cli`
  build needing to depend on a runtime script.

### 2.2 P22.7.2 — `lumen doctor` native ABI line

- `apps/cli/src/commands/doctor.ts`: gain one block that
  spawns the script and reads JSON:
  ```ts
  const probe = spawnSync('node', ['scripts/abi-drift-check.mjs', '--json'], { encoding: 'utf8' })
  const result = JSON.parse(probe.stdout || '{}')
  if (result.ok) {
    printOk(`Native ABI check (compiled ${result.compiled}, runtime ${result.runtime})`)
  } else if (result.reason === 'no-binding') {
    printOk(`Native ABI check (no better-sqlite3 binding present)`)
  } else {
    printFail(`Native ABI check (compiled ${result.compiled}, runtime ${result.runtime})`)
    failed = true
  }
  ```
  This is the same `[OK]/[FAIL]` pattern used for every
  other doctor line. The `printOk`/`printFail` helpers
  already exist. The `spawn` lives in a new tiny helper
  `apps/cli/src/abi-check.ts` so it is unit-testable
  with a stubbed `spawnSync` (a `vi.mock` of
  `node:child_process`).
- One test (`apps/cli/test/doctor-native-abi.test.ts`):
  a fixture with a known-ABI `better_sqlite3.node` →
  doctor reports OK. A second fixture with a *mismatched*
  ABI → doctor reports FAIL + non-zero exit.

### 2.3 P22.7.2 — `postinstall` hook

- Root `package.json` gains one line in `scripts`:
  ```json
  "postinstall": "node scripts/abi-drift-check.mjs"
  ```
  pnpm runs it after every `pnpm i`. The hook is
  idempotent (re-running on a clean binding is a no-op).
- `.changeset/p22-7-postinstall.md` documents the hook
  and the env escape hatch (`LUMEN_ABI_SKIP_CHECK=1`).
- The hook does **not** fail the install on rebuild
  failure — it prints the FAIL line and exits 0 so the
  install completes. (If a hard-fail were desired, that
  would be a P23+ change.)

### 2.4 P22.7.3 — operator guide

- `docs/ABI-DRIFT.md` (~150 lines):
  1. The drift story (when it happens)
  2. How `lumen doctor` reports it
  3. The postinstall hook's behaviour
  4. The `LUMEN_ABI_SKIP_CHECK` escape hatch
  5. CI behaviour (no TTY → no auto-rebuild → WARN)
  6. Manual rebuild via `pnpm rebuild:native`
  7. Relationship to P15's `onlyBuiltDependencies`
  8. Limits (only `better-sqlite3`; other natives are
     P23+)

## 3. 4-framework comparison

| Axis | Claude Code | OpenClaw | LangGraph 1.0 | Hermes Agent | Lumen (P22.7) |
| --- | --- | --- | --- | --- | --- |
| Install-side hardening | n/a (pure JS) | `pnpm.onlyBuiltDependencies`-style | pip `--force-reinstall` (manual) | n/a (pure JS) | `pnpm.onlyBuiltDependencies` (P15) |
| Drift detection | none | none | none | none | **YES — header parse, no probe** |
| Auto-rebuild | none | none | none | none | **YES — postinstall, TTY-only** |
| Doctor surface | `claude --doctor` (config check, no native check) | `claude doctor` (config check) | none | `hermes doctor` (config check) | **YES — `lumen doctor` gains `[OK/FAIL] Native ABI` line** |
| CI escape hatch | n/a | n/a | n/a | n/a | `LUMEN_ABI_SKIP_CHECK=1` |

P22.7 is the **first** framework in the comparison set to
ship an automatic drift hook. The implementation is
deliberately narrow (one dep, one header parser per
platform) because the surface is well-understood and a
general "detect-all-natives" tool would be P23+ scope.

## 5. Decision list

1. **Header parse, not probe.** Two reasons: probe can't
   diagnose the state it's diagnosing; probe couples
   detection to the broken runtime.
2. **Three platform parsers** (macOS / Linux / Windows),
   ~80 lines total. No `glob`, no `node-gyp`, no extra
   dependencies.
3. **Auto-rebuild on drift, TTY-only.** CI and non-TTY
   shells get a WARN line and exit 1; only an interactive
   TTY spawns `pnpm rebuild:native`.
4. **`LUMEN_ABI_SKIP_CHECK=1` escape hatch.** Documented
   in the changeset + operator guide.
5. **Postinstall hook in root `package.json`.** The hook
   fails open on rebuild failure (exit 0, WARN line).
6. **Doctor is read-only.** It reports; it does not
   mutate.
7. **New `@lumen/scripts` workspace** keeps the tier
   diagram honest: the script is not a CLI surface, it's
   a build tool.
8. **Narrow scope: better-sqlite3 only.** Adding more
   natives is P23+ scope.
9. **4 sub-tickets**, matching the P22.6 shape.
   `P22.7.1` (script + tests + changeset), `P22.7.2`
   (doctor + test), `P22.7.3` (postinstall hook), `P22.7.4`
   (operator guide).
10. **Minor bumps** on `@lumen/cli` and a no-op
    changeset for the root (the postinstall script is
    not a published artifact). P22.5 / P22.6 used minor
    bumps; P22.7 follows the same pattern.
