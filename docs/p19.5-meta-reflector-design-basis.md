## 2. 核心做法（每框架带 URL 引用）

### 2.1 LangGraph 1.0 — Cross-thread long-term memory
> **来源**: `https://docs.langchain.com/oss/python/concepts/memory.md`（fetched 2026-07-07）

- **两档 memory**：
  - **Short-term (thread-scoped)**：通过 checkpointer 持久化 State，按 `thread_id` 隔离。
  - **Long-term (cross-thread)**：通过 `BaseStore.put(namespace, key, value)`，
    `namespace` 是 tuple（如 `(user_id, application_context)`），**完全跨 thread 共享**。
- **跨 thread 的 isolation 机制**：custom namespace tuple，**不是 thread_id**。
  同一 user 不同 thread 共享同一 namespace → 自然 cross-thread consolidation。
- **Writing memories**：
  - "In the hot path"：在 agent loop 内调 `save_memories` tool，**写什么由模型决定**。
  - **"In the background"**：明确推荐用 cron / 定时 / 事件触发 background task 做 memory
    consolidation（"determining the frequency of memory writing becomes crucial"）。
    **原文**：*"Common strategies include scheduling after a set time period (with
    rescheduling if new events occur), using a cron schedule, or allowing manual
    triggers by users or the application logic."*
- **Procedural memory（最接近 Lumen MetaReflector 的对照）**：
  显式给出 "Reflection" / "meta-prompting" 模式：拿当前系统 prompt + 最近对话
  → LLM 重写自己的 instructions → `store.put` 覆盖。**这是替换式（overwrite），
  不是 trust delta 模式**。
- **Trust score 调整**：❌ 不存在。
- **10 run 触发合理性**：✅ 文档把"定时 background consolidation"列为推荐模式，
  但**未给具体数值**（"scheduling after a set time period"是模糊的）。Lumen 选
  10 run 是 lumen 自己的选择。

### 2.2 Claude Code — CLAUDE.md + auto memory 跨 session
> **来源**: `https://code.claude.com/docs/en/memory.md`（fetched 2026-07-07）

- **两套互补机制**：
  - **`CLAUDE.md`（人写）**：4 个 scope（managed / user `~/.claude/CLAUDE.md`
    / project `./CLAUDE.md` / local `./CLAUDE.local.md`），启动时全 load。
    带 path-scoped rules、import 语法、symlink 共享。**纯文本，无 trust。**
  - **Auto memory（模型自写）**：v2.1.59+ 引入。
    `~/.claude/projects/<project>/memory/MEMORY.md` 作 index + 主题文件。
    **每 session 启动 load "first 200 lines or 25KB"**（有 cap，不会无限增长）。
    Claude 决定写什么（"build commands, debugging insights, architecture notes,
    code style preferences"）。
- **Cross-session 共享**：
  - CLAUDE.md：通过文件系统 scope 共享（user / project / managed）。
  - Auto memory：per-repository（git repo 路径 hash），**全 worktree 共享**。
- **周期触发**：❌ 都不是周期性。
  - CLAUDE.md：用户手改。
  - Auto memory：session 内发生（`/memory` 界面可 toggle）。
  - **无 MetaReflector 等价的"跨 N session 合并"**。
- **Trust score 调整**：❌ 不存在；auto memory 是 markdown 文本 append。
- **10 run 触发合理性**：❌ Claude Code 模型自己"决定是否值得记"，
  无固定 N 触发模式。Lumen 强制每 10 run 触发比 Claude Code 更激进。

### 2.3 OpenClaw — 实际公开内容
> **来源**: `https://openclaw.ai/blog/lighter-core-sharper-claws`、`introducing-openclaw`、
> `https://soul.md`（fetched 2026-07-07）

- **OpenClaw 实际是 chat-platform agent gateway**：WhatsApp / Telegram / Discord /
  Slack / Teams 的 relay + AI agent，"open agent platform that runs on your machine
  and works from the chat apps you already use"。**公开博客全部是 release notes、
  security、performance 内容，无 memory 架构说明**。
- **`soul.md`（https://soul.md）**：是 **Clawd / steipete 写的哲学散文站**：
  "What Makes an AI, Itself?"，内容是关于 AI identity / memory fragility 的
  **哲学反思**，不是任何产品的 memory 系统。"SOUL.md" 在 OpenClaw 上下文中是
  概念比喻，不是技术机制。
- **Trust score**：❌ 无
- **10 run 触发合理性**：N/A
- **结论**：**用户任务里"OpenClaw 有 SOUL.md daily→long-term 蒸馏"的表述在公开
  资料中无证据**。`P19-DESIGN.md` §3.4/§5.4 的相应行**应当标注为未验证或删除**，
  本报告**不基于此做设计决策**。

### 2.4 Hermes Agent — fact_store + fact_feedback trust score
> **来源**: `https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/features/memory-providers.md`（Holographic 段，fetched 2026-07-07）

- **核心实现**：Holographic 插件 = Local SQLite + FTS5 full-text search + trust
  scoring + HRR (Holographic Reduced Representations)。
- **2 个工具**：
  - **`fact_store`**：9 个 actions — `add, search, probe, related, reason,
    contradict, update, remove, list`。`probe` 是 entity-specific algebraic recall；
    `contradict` 是自动检测冲突 fact。
  - **`fact_feedback`**：✅ **helpful/unhelpful rating → 训练 trust scores**。
- **Trust score 机制**（直接命中 Lumen P19.5 设计需求）：
  - `default_trust: 0.5`（0.0-1.0 区间）
  - **Asymmetric feedback**：helpful → +0.05，unhelpful → -0.10（**负面反馈权重
    是正面的 2 倍**，典型 "trust decays faster than it grows" 模式）
- **存储**：SQLite at `$HERMES_HOME/memory_store.db`（用户机器本机，对齐用户偏好
  中"lumen 不依赖外部 SaaS"原则）。
- **10 run 触发合理性**：⚠️ **Hermes 不是周期性触发**。Trust 在每次 `fact_feedback`
  立刻 ±0.05/-0.10 调整。**Lumen 选 10 run 做一次聚类 + ±0.1 delta 合并**，
  与 Hermes 的"每次反馈立刻小步调整"是**两种不同的设计哲学**：
  - Hermes 风格：高频小步、用户/模型驱动。
  - Lumen 风格：低频大步、后台批量聚类。
  两者**不冲突**（可以并存），但 Lumen 应当明确自己选的是**Hermes 的低频批量变体**。

## 4. 推荐方案

### 4.1 采纳 Hermes 模式做"trust delta 不复写"（**已对齐**）

- Hermes `fact_feedback` 的核心是"**原 fact 不变，只动 trust score**"——Lumen
  P19.5 `applyTrustDelta` 返回 patch（`recordId + delta + nextTrust + clusterSize`）
  而非 in-place mutation，**完全对齐**。
- 步长选择 Lumen `±0.1` 是合理的：每次 MetaReflector pass 合并 N≥2 个 fact 的
  信号，比 Hermes 单次 feedback 信号强 1 个数量级，步长放大 1-2 倍合理。
- **Asymmetric delta** 建议（**open question 1**）：Hermes 是不对称（+0.05/-0.10），
  Lumen 当前实现是**对称 ±0.1**。是否值得照搬 Hermes 的"负面信号权重 2x"？
  - 赞成：trust 衰减应该比增长快，**符合用户对"memory 应当渐进改进"
    的直觉**。
  - 反对：MetaReflector 是聚类驱动，负面 cluster（矛盾 fact）应当走
    `contradict` action 而不是负 trust 调整。
  - **建议**：本次 P19.5 commit 保持对称 ±0.1（不动），**单独立 P19.5.5 跟踪
    asymmetric 决策**。

### 4.2 10 run 间隔（**保持，但加文档说明**）

- 10 run 是 lumen 经验值，**不是 upstream 任何框架的默认值**：
  - LangGraph：cron / 时间驱动，不绑定 run 计数。
  - Claude Code：session 启动 load，无周期合并。
  - Hermes：event-driven（feedback 即调）。
- **建议**：在 `AgentConfig.metaReflection` JSDoc 中**显式标注**：
  > "Default 10-run interval is a Lumen-specific empirical choice. Compared to
  > LangGraph 1.0 (cron-driven background tasks), Claude Code (load-at-startup),
  > and Hermes Agent (event-driven fact_feedback), Lumen chooses a per-run counter
  > as the trigger to make the consolidation cadence observable in the agent loop.
  > See docs/P19-DESIGN.md §5 for the comparison."

### 4.3 Jaccard 相似度（**保留，接口可扩展**）

- Jaccard token overlap 是 deterministic e2e 友好选择，**符合 P19+ rule 4
  （public function must take Zod schema）和 PITFALLS.md 的"embedding 依赖
  会让 e2e flaky"经验**。
- **建议**：在 `ClusterOptions` 加 `embedder?: (text: string) => Promise<number[]>`
  可选字段，caller 传了就走 cosine，不传就 fallback 到 Jaccard。**本次 commit
  不实现 embedder 路径**，只把字段加进 schema（typed-but-unused 模式，避免
  P19+ rule 14 抽象噪音）。

### 4.4 修正 P19-DESIGN.md 中的 OpenClaw 行（**重要**）

- `P19-DESIGN.md` §3.4 / §5.4 把 OpenClaw 列为"daily→long-term 蒸馏"对照——
  **公开资料无证据**。`soul.md` 是哲学散文，OpenClaw 公开博客只覆盖 chat
  gateway / security / performance。
- **建议**：P19.5 commit 时同步 patch `P19-DESIGN.md`，把 OpenClaw 行降级为
  "未验证（public docs don't expose this; 4-framework comparison uses Hermes
  fact_store as the trust-delta reference）"。

### 4.5 与 Lumen 已有架构的契合度

| 既有约束 | 现状 | P19.5 契合度 |
|---|---|---|
| P19+ rule 11（middleware > boolean flag） | `metaReflection` 是 AgentConfig 字段 | ⚠️ `metaReflection` 是 config 而非 middleware。`meta-reflector.ts` L41-43 显式说明 "NOT a middleware: meta-reflection is a periodic job, not a step in the agent loop"，**符合 rule 11 的"扩展 Agent loop = middleware"排除条款** |

## 5. 需要 lumen 重新决策的 Open Questions（2 个）

### Q1: trust delta 是否 asymmetric（+0.1 / -0.1 vs Hermes +0.05 / -0.10）？

- **当前**：Lumen 实现为对称 `±0.1`（meta-reflector.ts L218）。
- **Hermes 模式**：helpful +0.05 / unhelpful -0.10（**负向 2x 权重**）。
- **决策建议**：
  - 若 lumen 想要"trust decays faster than it grows"（更保守），照搬 Hermes 模式：
    - 修改 `META_REFLECTOR_MAX_DELTA` 为 0.05（positive）和 0.10（negative）。
    - 在 `applyTrustDelta` 加 `sign: 'positive' | 'negative'` 参数或新
      `applyAsymmetricTrustDelta` helper。
  - 若保持现状对称，**需要在 e2e 测试覆盖"反向 cluster（矛盾 fact）应当走
    `contradict` action 删除而非负 trust"**。
- **影响范围**：小（一个常量 + helper），可在 P19.5 commit 内解决。

### Q2: 10 run 间隔是否应该是 config 而非常量？

- **当前**：`META_REFLECTOR_DEFAULT_INTERVAL = 10` 是 named export，
  `createClusteringMetaReflector({ interval?: 10 })` 是可选参数。
- **问题**：`AgentConfig.metaReflection = { interval?: number, strategy: 'clustering' }`
  （`TASKS.md` L762）声称 interval 是 config，**但 e2e 默认 10 来自常量
  而非 config 文件**。
- **决策建议**：
  - 保持 `META_REFLECTOR_DEFAULT_INTERVAL` 作为 named export（**常量层**），
    `createClusteringMetaReflector` 接受 `interval` 参数（**factory 层**），
    `AgentConfig.metaReflection.interval` **应当显式覆盖**（**config 层**）。
    三个层面都有显式 default。
  - 优先级：`AgentConfig.metaReflection.interval` > `createClusteringMetaReflector({ interval })`
    > `META_REFLECTOR_DEFAULT_INTERVAL`。
- **影响范围**：本次 commit 已经是这个结构，**只需补一个 e2e 覆盖"config
  override 优先级"**。

模式与 Hermes Agent fact_feedback 直接对齐（Hermes 是单次反馈 ±0.05/±0.10，

trust-delta 范式；LangGraph 1.0 提供 long-term memory + procedural reflection
存储底座但无 trust 概念；Claude Code 是 session-load 文本，无合并；OpenClaw
公开资料**没有 memory 蒸馏机制**，`soul.md` 是哲学散文站。Lumen 选 10 run 是
经验值，**不是 upstream 默认**。**
