# P20.7 — Agent Team Patterns

> **Status**: P19.3 + P19.4 已经为 lumen 提供了 4 种 sub-agent 编排
> 模式（sequential / parallel / handoff / supervisor），P20.7 是这些模式
> 的"组合"工作流。**不**新增 core middleware — 组合通过 apps/cli 端
> 的 `lumen run --team` 命令（计划中）实现，本文档是 P20.7 的设计基线。

## 1. 4 种编排模式回顾（P19.3 + P19.4）

| 模式 | 用途 | 核心实现 |
|---|---|---|
| **Sequential** | pipeline: A → B → C | `createSequentialSubAgent` 串行 N 个 sub-agent |
| **Parallel** | fan-out: A ∥ B ∥ C | `createParallelSubAgent` `Promise.all` + 60s timeout |
| **Handoff** | control transfer: worker → supervisor | `createHandoffSubAgent` 自动注册 handoff stub tool |
| **Supervisor** | gate per-step: continue/redo/abort | `createSupervisorSubAgent` judge function (haiku-style) |

详见 `docs/P19-DESIGN.md` §4。

## 2. Agent Team = 4 模式的组合 + 共享 PlanStore

Agent team 不是新模式，是上述 4 模式通过**共享 PlanStore**
组合出来的工作流：

```
                ┌─ handoff → worker-A (specialist)
                │
main agent ─────┼─ parallel → [worker-B, worker-C, worker-D] (research)
                │
                └─ supervisor → worker-E (gated critical task)
```

**关键约束**：
  - sub-agent 共享同一个 `PlanStore`（via `createPlanMiddleware({ planStore })`），
    让 handoff 链上的 plan 状态可见
  - 每个 sub-agent 的 system prompt 包含 "I am part of team X, role: Y"
  - sub-agent 失败时（throw AbortError），P20.4.2 catch 路径自动 save
    checkpoint 到 shared SqliteCheckpointStore，main agent 可以 resume
  - supervisor 模式用 haiku-style judge 决定 continue/redo/abort

## 3. Use case: code review team

```
┌─────────────────────────────────────┐
│  Main agent (orchestrator)          │
│  - reads diff, decides team roster   │
│  - handoffs to workers               │
└────────┬────────────────────────────┘
         │
   ┌─────┼──────────┬──────────┐
   │     │          │          │
   ▼     ▼          ▼          ▼
 lint  type-check test-run  review
 (sequential)   (parallel)  (handoff back to main)
```

每个 worker 完成后 write 一条 fact 到 PlanStore，main agent 在 handoff
事件 push 到主上下文时看到所有 worker 的 fact，做出最终决策。

## 4. Why no new core code

P20.7 需求列在 TASKS.md：
> [ ] P20.7 — Agent team（multi-agent workspace，借鉴 OpenClaw group-chat 礼仪 + Claude Code Task delegation）

但 lumen 在 P19 + P20.1-6 已经满足 agent team 的**所有底层原语**：
  - 4 种 sub-agent 编排（P19.3 / P19.4）
  - 共享 plan / checkpoint（P19.1 / P20.4）
  - 中间件链式组合（P19.0 createAgent factory）
  - CLI 端的 `lumen run` command 已经在用 createAgent factory + middleware（commit `e363f9d`）

剩下的工作全在 **apps/cli**：
  - 新增 `lumen run --team <path>` flag + `team.json` schema
  - 新增 `lumen team` 子命令（list/validate/show）
  - example team fixture in `apps/cli/test/fixtures/team.json`

不在 core 写新 middleware = 遵守 P19+ rule 15 (helper > abstract) +
tier 隔离（team 配置属于 CLI 使用层，不是 agent runtime 关注点）。

## 5. 4-framework 对比

P20.7 的"group-chat 礼仪"在 P19.5 design basis §0 / §2.3 已经标记为
**未验证**：OpenClaw 公开内容只有 chat-platform gateway，
`soul.md` 是 steipete 哲学散文站（不是产品 memory 系统）。本节不再
援引 OpenClaw group-chat 作为设计参照。

可对照的 real-world 实现：
  - **Claude Code Task delegation**（fetched 2026-07-07
    https://code.claude.com/docs/en/claude-code-task）：
    Task tool + 4 subagent_type（general-purpose / statusline-setup /
    Explore / Plan）；每个 sub-agent 是独立 context，main agent 通过
    tool call 传 prompt 召回。**lumen 对照**：SubAgentMiddleware 的
    `task` tool（commit `f22ffcd`）已经实现相同 pattern。
  - **LangGraph 1.0 StateGraph**（fetched 2026-07-07
    https://docs.langchain.com/oss/python/concepts/memory.md）：
    nodes + edges declarative graph；shared state 通过 channels。
    **lumen 对照**：Sequential/Parallel + shared PlanStore 已经满足
    graph pattern 的子集（linear chain + fan-out）。Lumen 不计划
    引入完整 graph runtime — 这是 P20+ backlog。
