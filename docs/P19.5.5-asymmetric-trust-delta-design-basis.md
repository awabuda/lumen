# P19.5.5 Asymmetric Trust Delta — Design Basis
## 4-framework re-fetch + Lumen MetaReflector decision record

> **Task**: 为 lumen P19.5.5 commit（asymmetric trust delta：负面 signal
> 权重 2x，对齐 Hermes `fact_feedback` 模式 +0.05/-0.10）准备 design basis。
> **方法**: 沿用 P19.5 design basis（commit `64c0a29`，2026-07-07）的 4-framework
> 对照，**重新 fetch 一次**确认 4 框架 trust 形状未变；本文是 P19.5.5 的
> **focused decision record**，不重复 P19.5 design basis §1-§6 的全框架对比。

---

## 0. 一句话结论

**Lumen P19.5.5 采纳 Hermes `fact_feedback` 模式：positive delta ≤ 0.05，
negative delta ≥ -0.10（负向 2x 权重）。P19.5.5 不改 `META_REFLECTOR_MAX_DELTA`
全局常量（仍是 0.1，保留 back-compat），而是新增两个 named export：
`META_REFLECTOR_POSITIVE_MAX_DELTA = 0.05` 与
`META_REFLECTOR_NEGATIVE_MAX_DELTA = 0.10`，以及一个 opt-in helper
`applyAsymmetricTrustDelta`。`applyTrustDelta`（对称）保持不变作为
default，`createClusteringMetaReflector` 默认继续调对称版本。`AgentConfig.metaReflection`
加 `asymmetric?: boolean` 字段（默认 false），true 时
`createClusteringMetaReflector` 自动调 `applyAsymmetricTrustDelta` 而非
`applyTrustDelta`。**

## 1. 决策记录（hard-call decisions）

### 1.1 Asymmetric 形状：+0.05 / -0.10（**采纳**）

| 选项 | 形状 | 优点 | 缺点 |
|---|---|---|---|
| **A. 对称 `±0.1`**（Lumen P19.5 现状） | `META_REFLECTOR_MAX_DELTA = 0.1` 双向 | 简单；正面负面权重一致 | "trust decays faster than it grows" 直觉违反 |
| **B. Hermes 镜像 `+0.05/-0.10`** | 负向 2x 权重；单次 pass 仍 cap 在 ±0.1 范围 | 符合 "trust decays faster than it grows" 直觉；唯一有真实 fetch 证据的对照 | 与对称版本并存导致 mental overhead |
| **C. 自定义 `+0.07/-0.07`** | lumen 自己折中 | 无 framework 对照 | 缺依据 |

**Decision: B**（Hermes 镜像）。理由：
- Hermes 是**唯一**公开有 trust-delta 形状的 framework（P19.5 design basis §0 表验证）
- Lumen MetaReflector 是"批量合并 N≥2 fact 信号"，Hermes 是"单次 feedback"
  → Lumen 步长应比 Hermes **略大**或**一致**，不应该更大
- P19.5 design basis §5 Q1 已明示推荐 asymmetric，**本次 commit 把决策落定**

### 1.2 Default 保持对称 + opt-in 切到 asymmetric（**采纳**）

**Decision: `applyTrustDelta`（对称）保持 default，`applyAsymmetricTrustDelta`
是新增 opt-in helper。`AgentConfig.metaReflection.asymmetric?: boolean` 默认 false。**

理由：
- Back-compat：现有调用方不传 `asymmetric` 字段时行为不变，**不需要
  migration note / changeset major bump**
- P19.5 design basis §3 已记录 "asymmetric 是 lumen 自己选的方向，
  与 upstream 任何 framework 的 default 都不一样"——保持对称为 default 是
  最安全的迁移路径
- Opt-in 字段遵循 P19+ rule 4（public function takes Zod schema）——加
  `asymmetric: z.boolean().optional()` 到 `MetaReflectionConfigSchema`，
  strict mode 拒绝未知字段

### 1.3 不引入"矛盾 fact 应该走 `contradict` action"的扩展（**采纳：不做**）

P19.5 design basis §4.1 反方意见："负面 cluster（矛盾 fact）应当走
`contradict` action 删除而非负 trust 调整"。

**Decision: 不在 P19.5.5 引入**。理由：
- `contradict` action 是 hermes `fact_store` 的 9 个 action 之一
  （P19.5 design basis §2.4），Lumen 没有等价 action——Lumen 当前只有
  `BaseMemoryStore.search/put/get/delete` 接口（P19.5 design basis §3.5）
- 引入 "contradict → delete" 路径需要在 core tier 改 `BaseMemoryStore`
  接口（违反 P19+ rule 12：state schema 不允许往 root state 偷加字段；
  BaseMemoryStore 是 memory tier 与 core tier 的边界接口）
- **不在 P19.5.5 范围**：asymmetric delta 是**纯数值改动**，P22+ backlog
  的 "negative cluster → store.delete" 是独立 P-ticket，需要独立 4-framework
  fetch（LangGraph 1.0 Trustcall 第三方库已经提供 JSON patch-based
  memory update + delete，可作为下次 fetch 的对照——见 §3.1）

### 1.4 步长放大不变（**采纳：保留 logarithmic 衰减**）

P19.5 design basis §3 表"Logarithmic 衰减"行确认：
`Math.log(1 + ratio * (Math.E - 1))` 形状 cluster size=2 → 0.07，
size=10 → 0.1。

**Decision: asymmetric helper 沿用 logarithmic 衰减，只换 cap（positive=0.05
而非 0.1；negative=-0.10 保留为 absolute magnitude=0.10，等于对称版的
magnitude）。**

理由：
- Logarithmic 衰减是 cluster size 的合并强度，与 sign 无关
- Asymmetric 只改 sign 的权重，不改 cluster size 的合并曲线
- asymmetric 的 cluster of 10 → positive=+0.05 / negative=-0.10（不是
  -0.05），**magnitude 仍由 META_REFLECTOR_MAX_DELTA cap = 0.10 兜底**

### 1.5 不改 `applyTrustDelta` 接口（**采纳：保留 back-compat**）

`applyTrustDelta` 当前签名：
```ts
applyTrustDelta(cluster, representative, interval?: number): TrustDeltaPatch
```

`TrustDeltaPatch` 字段：`recordId, delta, nextTrust, clusterSize`

**Decision: 接口不变。** 新增 helper：
```ts
applyAsymmetricTrustDelta(
  cluster,
  representative,
  interval?: number,
  positiveMax?: number,  // default 0.05
  negativeMax?: number,  // default 0.10
): TrustDeltaPatch
```

返回同样的 `TrustDeltaPatch` 形状（delta sign 已不对称；nextTrust
仍 cap [0, 1]）。

`createClusteringMetaReflector({ ..., asymmetric?: boolean })` 内部
`if (asymmetric) patches.push(applyAsymmetricTrustDelta(...)) else patches.push(applyTrustDelta(...))`。

## 3. 接口草案（API sketch）

### 3.1 新增 named export

```ts
/** Positive-side max delta for asymmetric trust adjustment (Hermes mirror). */
export const META_REFLECTOR_POSITIVE_MAX_DELTA = 0.05

/** Negative-side max delta magnitude for asymmetric trust adjustment. */
export const META_REFLECTOR_NEGATIVE_MAX_DELTA = 0.10
```

### 3.2 新增 helper function

```ts
export const applyAsymmetricTrustDelta = (
  cluster: FactCluster,
  representative: MemoryRecord,
  interval: number = META_REFLECTOR_DEFAULT_INTERVAL,
  positiveMax: number = META_REFLECTOR_POSITIVE_MAX_DELTA,
  negativeMax: number = META_REFLECTOR_NEGATIVE_MAX_DELTA,
): TrustDeltaPatch => {
  // ... 与 applyTrustDelta 相同结构，但 cap 用 positiveMax / negativeMax
  // ... 保持 logarithmic 衰减
}
```

### 3.3 `createClusteringMetaReflector` 加 asymmetric 选项

```ts
export const createClusteringMetaReflector = (
  options: {
    interval?: number
    similarityThreshold?: number
    kind?: string
    asymmetric?: boolean  // NEW
  } = {},
): BaseMetaReflector => {
  // ...
  return {
    id: 'clustering',
    async reflect(store) {
      // ...
      for (const cluster of clusters) {
        const representative = await store.get(cluster.representativeId)
        if (!representative) continue
        patches.push(
          asymmetric
            ? applyAsymmetricTrustDelta(cluster, representative, interval)
            : applyTrustDelta(cluster, representative, interval)
        )
      }
      return patches
    },
  }
}
```

### 3.4 无 core-tier `MetaReflectionConfig`（**verify in tree 降级**）

**Verify in tree（2026-07-14）**：`grep -rnE "metaReflection|MetaReflection"
packages/ apps/` 返回 **0 命中**。`createClusteringMetaReflector` 是
memory tier (`packages/memory/src/meta-reflector.ts`) 直接 export，core
tier (`@lumen/core`) 不持有 `MetaReflectionConfig` 类型——TASKS.md L762
的 `AgentConfig.metaReflection = { interval?, strategy: 'clustering' }`
是 P19.5 design 描述，**实际没落地到 AgentConfig**。

**Decision: 不在 P19.5.5 触碰 core tier `AgentConfig`。opt-in 通过
`createClusteringMetaReflector({ asymmetric: true })` 直接传。**

理由：
- 改 `AgentConfig.metaReflection` 等于在 core tier 公共 API 上加 boolean flag，
  **违反 P19+ rule 11**（middleware > AgentConfig boolean flag）
- `createClusteringMetaReflector` 已是 memory tier factory，opt-in 参数
  是 P19+ rule 15（helper > abstract class）允许的扩展点
- TASKS.md L762 提到 `AgentConfig.metaReflection` 是 P19.5 spec 的
  future state（**未实现**），P19.5.5 不补这个债——是 P22+ 独立 P-ticket

**配置面降级**：`asymmetric` 不是 config-file 字段，是 factory 参数。
CLI 侧 (`lumen reflect meta`) 如果需要配置，需要 `reflect.ts` 加 `--asymmetric`
flag——P19.5.5 implement commit **不做**（CLI surface 在 P19.6 已经闭合）。

## 6. 不在 P19.5.5 范围（明确降级）

1. **Negative cluster → store.delete via `contradict` action**（P19.5 design
   basis §4.1 反方意见）——需要改 `BaseMemoryStore` 接口（memory tier 与
   core tier 边界），是 P22+ 独立 P-ticket。LangChain Trustcall 库已提供
   对照，下次 design basis fetch 时引用。
2. **完全用 `applyAsymmetricTrustDelta` 替换 `applyTrustDelta`**（即不
   保留对称版本）——破坏 back-compat，与 P19+ rule 16（4-framework fetch
   before declaring a new abstraction）违背。需要先收集 ≥ 1 个 production
   run-end reflection 信号再做 major migration。
3. **Trust score < 0 时强制删除 fact**——同上，需要 `BaseMemoryStore`
   接口扩展。
4. **`applyAsymmetricTrustDelta` 加 LLM classifier（heuristic 或 LLM）
   决定 cluster 是"正面合并"还是"负面合并"**——P19.5 当前 cluster 形状
   只是"内容相似"，不区分"新事实确认"与"旧事实反驳"。**这是一个独立
   的"cluster sign 标注"问题**，需要在 Jaccard similarity 之外加
   "embedding-based semantic contradiction detection"——是 P22+ 候选，
   不在 P19.5.5 范围。
